### 后续修复：Windows 端口排除范围导致 8080 bind 失败

**现象**：用户运行 `python gui_main.py` 报 `[Errno 13] / winerror 10013`，8080 无法 bind。
**根因**：Hyper-V/WSL2 动态保留了 7790-7889 和 7991-8090 端口范围；旧版 `_pick_available_port`
用 `SO_REUSEADDR` 测试 bind，但 Windows 上 SO_REUSEADDR 会绕过排除范围检查，导致测试通过
但 uvicorn 实际 bind 失败。
**修法**（`gui_main.py`）：
1. 测试 bind 时去掉 `SO_REUSEADDR`，与 uvicorn 默认行为一致
2. 新增 `_get_windows_excluded_port_ranges()` 查询 `netsh interface ipv4 show excludedportrange protocol=tcp`，显式跳过保留范围
3. 候选端口加 18080/28080/38080/48080 高位端口（几乎不会被动态保留）
4. 全部失败时 `bind(("127.0.0.1", 0))` 让 OS 分配
**验证**：8080 被正确跳过，自动切到 18080。
**用户建议**：可在 `.env` 加 `GUI_PORT=18080` 固定端口，避免每次扩展配置都要改。

### 后续修复：扩展连接失败 + 设置页接口地址显示 None

**现象**：用户截图显示 Chrome 扩展侧边栏「连接失败」，设置页「接口地址: None」。
**根因**：
1. 端口修复后 NiceGUI 跑在 18080，但扩展侧边栏默认 URL 仍为 8080，导致 fetch 失败
2. `local_api_url` 只通过 `routes.py` 的参数传递；设置页/概览页直接调 `service.status()` 时拿不到

**修法**：
1. `app/extension/service.py`：加 `local_api_url` 字段 + `set_local_api_url()` 方法；
   `status()` 优先用实例字段（路由参数仍可覆盖）
2. `gui_main.py`：启动时 `get_ingest_service().set_local_api_url(local_api_url)` 注入
3. `app/gui/pages/settings.py`：加「复制接口地址」按钮（用 `navigator.clipboard.writeText`）
4. `dist/chrome_extension/sidepanel.js`：默认不再填 8080，留空并提示用户从 NiceGUI 复制

**验证**：
- 路由 `/api/extension/status` 返回 `local_api_url=http://127.0.0.1:18080`
- `service.status().local_api_url` 也返回 `http://127.0.0.1:18080`
- 全量测试 341 全过

**设计教训**：配置型数据（URL、端口、路径）应存为服务实例字段，所有调用方都从同一处取，
不要只在某个调用路径上用参数传递——会导致 UI/路由状态不一致。

### 后续修复：Chrome 扩展连接失败（CORS）

**现象**：用户截图显示扩展点「测试连接」报 "Failed to fetch"。
**根因**：MV3 扩展从 `chrome-extension://` 上下文 fetch `http://127.0.0.1:18080` 时被 CORS 拦截，
即使 manifest 里有 `host_permissions`，某些场景下仍需服务端显式返回 CORS 头。
**修法**（`gui_main.py` main()）：
- 加 `CORSMiddleware`，`allow_origin_regex` 匹配 `chrome-extension://.*`、`http://127.0.0.1:\d+`、`http://localhost:\d+`
- `allow_credentials=False`（扩展用 `X-Extension-Token` 头传令牌，不用 cookie）
- `allow_methods=["GET","POST","OPTIONS"]`，`allow_headers=["*"]`
- 服务仅监听 127.0.0.1，开放所有头是安全的
**验证**：
- OPTIONS preflight 返回 200 + 正确 CORS 头
- GET ping 带 Origin 返回 200 + Allow-Origin
- 恶意 Origin（evil.com）不返回 CORS 头（拒绝跨域）
- 全量 341 测试通过

**改进 sidepanel.js 报错**：fetch 失败时区分网络/CORS 错误与 HTTP 错误，
给出 4 条可能原因清单（服务未启动/CORS/扩展需重载/防火墙）。

### 令牌规格
- 生成方式：`secrets.token_urlsafe(32)` → 32 字节随机数据，base64url 编码
- 长度：**43 个字符**
- 字符集：A-Z, a-z, 0-9, `-`, `_`（无 `=` 填充）
- 示例：`Ni--nX1XxIWmFJABlFQHYvdc_24fvEZ5sI_a3KWTOx8`
- 设置页只显示前 8 位（脱敏），完整令牌在 `data/extension_token.txt` 文件中

### 后续修复：采集按钮报"当前标签页不是 Instagram（未知）"

**现象**：用户在 Instagram 创作者主页点「采集当前博主」，日志反复报"当前标签页不是 Instagram（未知）"。
**根因**：MV3 扩展的 `chrome.tabs.query` 返回的 `Tab` 对象，`tab.url` 字段需要 `tabs` 权限才能读取。
当前 manifest 只申请了 `activeTab`（给内容脚本访问权，不给 `chrome.tabs.query` 的 URL 字段），
所以 `tab.url` 是 undefined，前置校验失败。
**修法**（`dist/chrome_extension/sidepanel.js`）：
- 不再硬依赖 `tab.url`：tabUrl 已知则快速校验；为空时打 warn 日志，继续往下走
- 注入 content.js 后，content.js 用 `window.location.href` 自查 URL，错误信息更具体
- 加 5 秒超时（`sendWithTimeout`），避免 content.js 未就绪时无限挂起
- 注入错误处理更健壮（匹配 "already / same id / already exists"）

**配套修法**（`dist/chrome_extension/content.js`）：
- 区分两种失败：非 Instagram 页面 vs Instagram 但非创作者主页
- 非创作者主页错误信息给出示例 URL：`请打开 https://www.instagram.com/<username>/ 这样的主页`

**教训**：MV3 扩展权限模型与 MV2 差异大。`activeTab` 只覆盖内容脚本注入，
读取 `tab.url` / `tab.title` / `tab.favIconUrl` 必须额外申请 `tabs` 权限。
如果不想申请 `tabs`（隐私考量），就让 content script 内部用 `window.location` 自查。

### 后续修复：注入 content.js 报 "Cannot access contents of the page"

**现象**：用户在 Instagram 主页点「采集当前博主」日志报：
- `Cannot access contents of the page. Extension manifest must request permission to access the respective host.`
- `Could not establish connection. Receiving end does not exist.`

**根因**：`activeTab` 是临时权限——只在用户**点击扩展图标的瞬间**授予 active tab。
用户先点扩展图标打开 sidepanel，然后切到 Instagram tab 时 activeTab 已不覆盖那个 tab，
`chrome.scripting.executeScript` 注入失败，后续 `chrome.tabs.sendMessage` 自然也连不上。

**修法**（`dist/chrome_extension/manifest.json`）：
- `host_permissions` 加 `https://www.instagram.com/*` 和 `https://instagram.com/*`
- 让扩展能在任意 Instagram 网页稳定注入脚本，不依赖 activeTab 的临时授权
- 仍然**不**申请 `cookies` / `webRequest` / `<all_urls>` / `tabs`
- 仍然不读 Cookie / localStorage / Session

**配套修法**（`dist/chrome_extension/sidepanel.js`）：
- 注入错误分类处理：「已注入」静默忽略、「Cannot access contents / host permission」
  给出明确诊断（让用户重新载入扩展）、其他错误打 warn

**教训**：MV3 扩展要采集某网站的 DOM，必须在该网站的 host_permissions 里声明。
activeTab 只适合"用户主动点击后立即对当前 tab 操作一次"的场景，不适合 sidepanel
+ 多 tab 工作流。这是与 MV2 最大的差异之一。
